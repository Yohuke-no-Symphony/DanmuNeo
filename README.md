<h1 align="center">Yohuke Danmu Neo</h1>

<p align="center">面向 B 站直播同传的跨平台桌面工作台</p>

Yohuke Danmu Neo 是一个面向 B 站直播同传工作的桌面工具，基于 .NET、Avalonia 和 WebView 构建。它把直播监听、同传发送、歌词发送、弹幕转发、屏蔽词替换和多工作区管理集中在一个可配置的工作台里。

![](./Screenshots/1.webp)

## 功能

- 多工作区与多直播间管理，切换房间时共用同一套 Dock 工作台布局。
- 工作区、追帧、输入框、SC、弹幕、历史、歌词、转发、日志、禁言管理、账号粉丝牌、直播打点截图和直播记录十三个独立 Dock 面板，支持拖拽停靠、分栏、标签组合和独立置顶的浮动窗口。
- 默认、同传、歌词、转发四套内置布局，以及自定义布局的保存、另存、重命名和删除。
- 按昵称分页查找直播间；输入纯数字时同时匹配主播 UID 和房间号，标记命中来源并合并相同房间及短号。打开新增房间窗口时，按目标工作区使用的账号加载正在直播的关注；留空查找可刷新，无账号时仍可匿名查找昵称、UID 和房号。手动房间信息直接显示，可离线添加。
- B 站账号管理，支持全局、工作区、直播间和转发规则级账号选择。
- 账号设置展示在线验证状态、真实昵称和 UID，支持手动刷新；启动、登录及 Cookie 编辑后验证，确认失效的账号会拦截同传、歌词和转发发送。网络异常显示暂时无法验证，账号凭据和自定义名称会保留。
- 直播弹幕监听、同传输入、发送历史记录和 Excel 导出。
- 开始监听和断线恢复时补拉服务器近期普通弹幕，与实时消息保守合并，历史项标明来源；补拉失败不影响实时监听。
- 默认将收到的普通弹幕、SC、礼物和上舰记录保存为 UTF-8 文本日志，按公开房间和监听会话分文件、跨日轮转；在“杂项”中可即时开关留档并打开目录。
- 同传输入框底部可选择当前发送账号已解锁的弹幕颜色和位置，切换后立即保存；同传、歌词和转发发送使用各自发送账号在目标直播间的配置。
- 弹幕在用户名前显示粉丝牌与等级，牌名最多展示三个字；点击 SC 或弹幕用户名可复制完整名字，点击正文可添加到同传输入框；有房管或主播权限时可右键禁言用户。
- 禁言管理可切换账号，汇总该账号在全部已添加直播间中有权限管理的名单；支持 UID／昵称查找、主动禁言和解除禁言，部分房间失败时保留其余结果。此面板不依赖当前房间选择。
- 账号粉丝牌默认跟随当前房间实际使用的账号，也可固定选择账号，支持刷新、佩戴和摘牌。每个账号可独立开启自动换牌；仅随活跃房间匹配真实主播 UID，没有对应牌子且完整牌墙已确认时摘牌。手动操作会先关闭并保存自动设置，网络失败或牌墙不完整时保留当前牌子。
- 弹幕支持文字与表情图片混排及整条表情包，图片下载失败时保留原文。
- 下翻历史弹幕时暂停自动回顶并保持阅读位置，返回顶部后恢复跟随；点击弹幕面板标题栏的“回到顶部”按钮或按 `Alt+Home` 可直接回顶并恢复跟随，快捷键支持在设置中修改，在同传输入框内同样生效。
- SC 列表以单行显示上舰记录，舰长为蓝色、提督为紫色、总督为橙色，点击上舰记录可复制完整用户名。
- 歌词库管理、歌词时间轴发送、快进快退微调和已发送去重；选择仅翻译时，缺少译文的歌词会复制或发送原文。
- 同传、歌词和转发按实际发送账号在目标房间的字数上限分段，每段保留完整标识符；失败后发送相同内容仅补未成功部分。
- 明确限频时可自动重试最多 2 次；被屏蔽及结果不明的网络失败不自动重发，同传草稿保留失败原因。
- 直播播放器追帧、静音自动播放、音量控制和画面健康检查。
- 直播打点截图保留当前视频原始分辨率的 PNG，记录开播时间、从开播至抓图的经过时间及实际抓图时间；未知开播时间保持未知。默认 Alt+P，可在快捷键设置中修改，同传输入框和原生播放器获得焦点时同样生效。
- 永久截图图库可按房间和开播场次筛选、编辑自动保存的备注，并导出单张、选中项或当前筛选全部，导出图附带时间和备注。原图和记录始终保留，导出、房间删除及清理缓存不会清空图库；保存失败可重试，退出会先完成原图与备注保存，取消未完成的导出。
- 直播记录为每个房间标签独立打开一份 LiveMarker YAML 文件，支持七色事件打点、时间前缀输入、编辑与撤销重做、自动保存及 TXT／彩色 Excel 导出。
- 弹幕转发规则，支持来源直播间、发送人 UID、内容正则、开闭符号组和发送账号覆盖。
- 屏蔽词替换库，可同时作用于同传输入和歌词发送。
- 可配置快捷键、自动备份保留数量、缓存清理和配置导出。
- 完整界面支持简体中文和英文，支持跟随系统、即时切换和记忆语言选择。
- 歌词列表获得焦点时，默认使用 `Cmd+C`（macOS）或 `Ctrl+C`（Windows/Linux）复制选中行，可在“快捷键 → 歌词 → 复制歌词”中改绑；输入框保留正常复制和粘贴。
- 默认按 Tab 轮切当前工作区的同传样式预设，在同传输入框内同样生效。
- 通过顶部菜单打开视图、设置、布局管理、关于和手动更新检查；macOS 默认使用原生系统菜单，设置支持 `⌘,`。

## Dock 工作台与布局

工作台由十三个独立面板组成：工作区、追帧、输入框、SC、弹幕、历史、歌词、转发、日志、禁言管理、账号粉丝牌、直播打点截图和直播记录。工作区面板管理工作区与直播间，八个业务面板随当前直播间切换内容，日志和三个工具面板在整个应用会话中共享。所有工作区和直播间共用一套布局；切换直播间会保留面板排布，草稿、历史、歌词、转发配置和记录文件仍属于各自的直播间。

直播间状态、房间名称、房间号及监听按钮集中显示在主窗口标题栏中部。

### 调整面板与浮动窗口

- 拖动面板标题或标签，可以改变停靠位置、与其他面板组成标签组，或分成上下、左右排列；拖动分隔条调整各区域大小。
- 将面板拖出主窗口，可以创建浮动窗口；再次拖动其中的面板标题或标签，可以重新停靠到主窗口或其他面板组。
- 浮窗标题栏的图钉按钮可独立置顶该窗口。主窗口置顶时，浮窗也会跟随置顶；取消主窗口置顶后，启用了独立置顶的浮窗仍保持置顶。
- 点击面板的关闭按钮会隐藏该面板；关闭整个浮窗会隐藏其中的面板。通过“视图 → 面板名称”可以重新打开；如果面板已经显示，该菜单会切换到对应标签或激活其浮窗。

关闭追帧面板会停止播放，重新打开后保持停止。关闭其他面板会保留草稿、监听、歌词发送和转发。拖动、浮动、切换标签或应用布局时会保留播放会话和播放意图，原生播放器重新挂载后恢复播放。

### 内置布局与自定义预设

“布局”菜单提供四套内置预设，可按工作方式切换：

| 预设 | 初始排布 |
| --- | --- |
| 默认 | 左侧为工作区，中间为追帧与输入框；右侧上方为 SC，下方以标签组合弹幕、历史、歌词、转发、日志和三个工具面板。 |
| 同传 | 保留追帧与输入框，右侧分别显示 SC、弹幕及历史／日志／工具标签组；歌词和转发默认隐藏，可从“视图”菜单打开。 |
| 歌词 | 中间主区域显示歌词，下方为输入框；追帧和其他业务面板放在右侧。 |
| 转发 | 中间主区域显示转发，下方为输入框；追帧和其他业务面板放在右侧。 |

调整好排布后，可以通过“布局”菜单管理自己的预设：

- **另存为布局…**：将当前排布保存为新的自定义预设，并切换到该预设。
- **保存当前布局**：用当前排布覆盖正在使用的自定义预设；选中内置预设时此项不可用。
- **管理布局…**：应用、另存、重命名或删除预设；内置预设不能改名或删除。
- **恢复默认布局**：重新应用“默认”排布，保留已保存的自定义预设。

当前排布与命名预设分别保存。拖动、缩放、切换活动标签、隐藏面板及移动浮窗都会自动记忆，重启后恢复；这些操作不会自动覆盖命名预设。希望以后从“布局”菜单重新应用调整后的排布时，需要执行“保存当前布局”或“另存为布局…”。删除正在使用的自定义预设会保留当前排布，并将当前预设标识回退为默认。

新增工具面板会加入内置布局的现有工具标签组。已有布局及自定义预设升级时保持原排布，新面板默认隐藏，可从“视图”菜单打开。

### 日志与辅助窗口

“已保存”等操作提示及业务错误统一进入日志面板。日志在本次应用会话中共享，保留最近 2000 条，支持 INFO、WARNING、ERROR 级别筛选、全文搜索、异常详情展开、复制和清空。切换房间、隐藏或浮动面板不会丢失日志；错误显示未读数，保持当前正在操作的面板。新布局默认将日志面板放入历史所在的标签组，旧布局升级时保留原排布，可通过“视图 → 日志”打开。日志内容不跨启动恢复，诊断中的账号凭据及播放器会话令牌会自动隐藏。

发送失败时可展开该条错误查看最终请求的诊断：`code`、独立的 `message`／`msg`、房间号、文本长度与 SHA-256 摘要、颜色、模式、`rnd`，以及有值的 Cookie 字段名称。请求正文和 Cookie 值不会作为诊断字段保存；响应文本经过脱敏并限制长度，复制日志会包含这些详情。

B 站账号的浏览器登录、二维码登录和手动 Cookie 输入会保留已有的 `buvid4`、`buvid_fp` 设备字段。旧版已过滤掉的字段无法在升级后自动恢复；遇到发送问题时，可在账号设置中重新抓取浏览器 Cookie，或重新输入包含设备字段的 Cookie，再通过日志详情确认请求是否携带。缺失设备字段本身不被当作登录失效。

在 macOS 的“设置 → 外观”中可即时切换窗口内菜单。无论选择哪种模式，系统应用菜单中的“设置…”和 `⌘,` 都保留。设置与布局管理打开后，主窗和业务浮窗暂停交互；关闭设置窗口会保存配置并结束快捷键录制。

工作区设置仅通过工作区右键菜单中的“工作区设置”打开独立窗口，不在全局设置中显示。工作区名称、账号覆盖、标签组和直播间资料统一在该窗口中编辑；点击“保存”或关闭窗口都会保存修改。

在“设置 → 外观 → 配色方案”下拉框中，可以选择系统、浅色或深色。工作台使用统一的表面、细边框、紧凑工具按钮和圆角面板，活动标题与选中标签使用系统强调色。选择后即时应用到主窗、业务浮窗和辅助窗口，并保存配色偏好。

“帮助 → 检查更新”不受启动自动检查开关限制，会显示检查结果。歌词库选择器、设置、布局管理、关于和更新均使用独立窗口。

## 直播记录

通过“视图 → 直播记录”打开独立记录面板。新建文件时选择 YAML 保存位置，应用从 B 站获取本场直播时长，以“本机采集时刻减去直播时长”建立文件的 `StartTime`。直播未开始或取时失败时不会替换当前文件；建立起点以后无需保持网络、播放器或弹幕监听。

每场直播手动新建一个文件。打开已有 `.yaml`／`.yml` 时，始终使用其中的 `StartTime`，不重新向 B 站校准；旧 LiveMarker 文件中已保存的 `RealDateTime` 和 `LiveTime` 均独立保留。旧文件未带时区的日期按当前电脑本地时间解释，新保存的日期包含时区偏移。

输入首个有效字符时锁定打点时间，Enter 提交。输入前缀如 `25:01:02 事件内容` 可直接指定直播内时间，支持半角／全角冒号和点；小时累计显示，超过 24 小时不回绕。实际时间独立记录输入开始的时刻；编辑直播时间、撤销、保存和导出都不会重算它。Escape 锁定输入时间，Shift+Escape 解锁。

表格可修改直播时间、内容和七色标记，实际时间列只读。面板选项可关闭默认开启的自动保存或隐藏实际时间列。切换房间、隐藏面板和浮动窗口保留各标签的文件、草稿及撤销历史；重启后恢复上次文件路径，撤销历史仅保留在本次应用会话。不同工作区中指向同一 B 站房间的标签仍各自独立，同一个文件不能同时在两个标签中写入。

TXT 和 Excel 均按直播时间排序，固定导出直播内时间、实际时间、内容和颜色，Excel 保留颜色高亮。关闭文件、更换文件、删除房间／工作区或退出前会完成保存检查；未提交的打点草稿也可在确认时保存。工作区分享与配置备份仅包含配置，外部 YAML 记录文件应单独保管。

记录面板获得焦点时，`Cmd/Ctrl+N`、`O`、`S` 分别新建、打开和保存，`Cmd/Ctrl+Alt+S` 另存为，`Cmd/Ctrl+Shift+T` 导出文本，`Cmd/Ctrl+Shift+E` 导出 Excel，`Cmd/Ctrl+1` 至 `7` 选色；可在快捷键设置中修改。文本框保留自己的撤销、重做和删除，表格之外的快捷键不会操作记录文件。

## 界面语言

在“设置 → 外观 → 界面语言”中选择“跟随系统”、简体中文或 English，已打开的设置窗口、菜单、工作台面板、浮窗、右键菜单和播放器提示会即时刷新。语言选择保存在 `settings.json` 的 `Language` 字段中。切换语言会保留当前布局、草稿、快捷键录制和播放会话；工作区名称、歌词、弹幕及远端接口返回的内容按原文保留。日志保留记录发生时的文本。

语言包沿用 AegiNext 的外置 JSON 格式，源码位于 `Sources/Yohuke.DanmuNeo/I18n/Languages/`，构建和发布时复制到可执行文件旁的 `i18n/`。macOS App 对应 `Contents/MacOS/i18n/`。添加语言时，复制一份现有 JSON，设置 `LanguageName` 和有效的 `LanguageID`，保留 `Strings` 中的语义键与 `{0}` 等位置参数，翻译后放入该目录，重启应用即可出现在语言列表中。

英文语言包是必需的回退资源。其他语言缺少的条目会回退到英文；无效或重复 ID 的语言包会被排除。若保存的语言包暂时不可用，应用显示英文，并保留原语言选择，恢复语言包后可在下次启动继续使用。

## 环境

- .NET SDK 10.0 或更高版本。
- macOS、Windows 或 Linux 桌面环境。
- B 站账号 Cookie 用于发送弹幕和监听需要登录态的直播间。

## 开发

还原依赖：

```bash
dotnet restore Sources/Yohuke.DanmuNeo.sln
```

运行测试：

```bash
dotnet test Sources/Yohuke.DanmuNeo.sln --no-restore
```

启动应用：

```bash
dotnet run --project Sources/Yohuke.DanmuNeo/Yohuke.DanmuNeo.csproj
```

发布当前平台版本：

```bash
dotnet publish Sources/Yohuke.DanmuNeo/Yohuke.DanmuNeo.csproj -c Release
```

按当前操作系统生成发布包：Windows 仅生成 Windows x64 发布目录与 NSIS 安装器，macOS 仅生成 macOS ARM64 App 和 DMG。

```powershell
pwsh -NoProfile -File ./release.ps1 -Clean
```

脚本需在 Windows 或 macOS 上运行，只检查并调用当前平台所需的资源与打包工具；Windows 不会执行 macOS 图标转换、App 签名或 DMG 打包。Windows 还需要 NSIS 3.11 或更高版本：脚本依次查找 `-NsisPath` 指定的编译器、PATH 中的 `makensis` 和 Program Files 下的 NSIS。可通过 `-NsisPath "C:\Program Files (x86)\NSIS\makensis.exe"` 指定路径。工具与版本检查在清理输出目录和还原依赖之前完成。

Windows 安装器和 macOS DMG 的默认输出路径为：

- Windows 安装器：`Artifacts/Publish/Yohuke-Danmu-Neo-{版本}-win-x64-setup.exe`
- Windows EXE：`Artifacts/Publish/win-x64/Yohuke.DanmuNeo.exe`
- macOS：`Artifacts/Publish/Yohuke-Danmu-Neo-{版本}-osx-arm64.dmg`

发布使用自包含的非 single-file 模式。Windows 安装器包含完整发布目录，包括 `Yohuke.DanmuNeo.exe`、应用与 .NET 运行时 DLL、原生库、运行配置和 `i18n/` 语言包目录，无需预装 .NET。分发时使用 `*-win-x64-setup.exe`；`win-x64/` 保留为构建输出目录。macOS 的完整发布文件封装在 App 内，再打包为 DMG。

Windows 安装器默认安装到当前用户，可在向导中选择所有用户；两种范围分别登记到 HKCU 和 HKLM，并创建对应范围的开始菜单快捷方式。桌面快捷方式位于完成页，默认不勾选。重装或升级会先运行同一安装范围的旧卸载器，以移除旧包自有文件；不同安装范围不能共用同一目录。卸载只删除安装器记录的文件和由其创建的快捷方式，保留额外放入安装目录的文件及 `%APPDATA%\Yohuke.DanmuNeo` 用户数据。

静默安装支持 `/CurrentUser`、`/AllUsers` 和可选的 `/DesktopShortcut`；所有用户安装需要管理员权限。自定义目录 `/D=` 必须放在命令行最后，目录值不加引号（即使包含空格）。例如：

```powershell
Start-Process -FilePath ./Yohuke-Danmu-Neo-0.0.2-win-x64-setup.exe -Wait `
    -ArgumentList '/S /CurrentUser /DesktopShortcut /D=C:\Apps\Danmu Neo'
```

卸载可使用系统的“已安装的应用”、开始菜单中的卸载入口，或在安装目录运行 `Uninstall.exe /S /CurrentUser`（所有用户安装使用 `/AllUsers`）。请先关闭应用再安装或卸载；文件被占用时操作会报错并保留文件。

安装模板和清单生成逻辑位于 `Packaging/Windows/`。macOS 语言包位于 `Yohuke Danmu Neo.app/Contents/MacOS/i18n/`，随 App 一起进入 DMG。发布脚本会在生成 Windows 安装器、组装 macOS App 和准备 DMG 内容时核对全部语言包；缺少必需的英文包、其他随源码发布的语言包或内容不一致时会终止发布。

版本默认读取项目的 `AssemblyVersion`，可通过 `-Version` 覆盖，接受两到四段数字且各段不超过 65534。Windows 安装器的文件版本补齐为四段，产品显示版本保留传入值。

DMG 默认使用 ad-hoc 签名，内含应用、`Applications` 快捷方式和中文首次打开说明。如需使用 Developer ID 证书签名，可执行：

```powershell
pwsh -NoProfile -File ./release.ps1 -Clean -MacCodeSignIdentity "Developer ID Application: Example Company (TEAMID)"
```

脚本不会自动提交 Apple 公证。未公证版本在其他 Mac 上首次打开时，请按 DMG 内的《首次打开说明》处理。

## 数据目录

应用配置默认写入系统 ApplicationData 下的 `Yohuke.DanmuNeo` 目录。主要文件包括：

- `settings.json`：全局设置、快捷键、屏蔽词替换库和符号组。
- `layouts.json`：全局当前布局、自定义预设、隐藏面板和浮窗位置；首次使用时迁移旧侧栏和左右列宽，之后独立保存。
- `accounts.json`：B 站账号配置。
- `Captures/`：永久截图图库，每条记录独立保存 `original.png` 与 `capture.json`，包含房间、开播场次、时间及备注，不属于缓存或配置备份。
- `workspaces.json`：工作区、直播间和转发规则。
- `lyric-library.json`：本地歌词库。
- `Backups/`：自动备份文件。
- `Corrupt/`：损坏配置的留存副本。
- `DanmuLogs/`：收到消息的永久文本留档，独立于缓存和配置备份；清理缓存或删除房间不会删除留档。同房间在不同工作区的监听各自留档，自动重连沿用会话，手动停止后重新监听创建新文件。
- `temp/emots/`：弹幕表情图片缓存，纳入缓存体积统计和清理。

也可以在应用的“杂项”设置页打开配置目录、缓存目录或导出全部备份。

布局保存采用 300 ms 防抖与串行原子写入，并沿用备份保留数量设置。损坏的布局先留存在 `Corrupt/`，再尝试最新有效备份，无法恢复时使用默认布局。浮窗恢复时会根据当前显示器工作区修正越界位置。

## 测试

测试项目位于 `Sources/Yohuke.DanmuNeo.Tests`，覆盖状态迁移、账号选择、播放器 HTML、歌词时间轴、屏蔽词替换、快捷键绑定、转发规则和历史导出等核心逻辑。提交前请至少执行：

```bash
dotnet test Sources/Yohuke.DanmuNeo.sln --no-restore
```

发布脚本的平台分流、前置检查和 NSIS 清单构建使用独立的 PowerShell 测试，需要 Pester 5.7.1 或更高版本：

```powershell
pwsh -NoProfile -Command "Invoke-Pester -Path ./Sources/Yohuke.DanmuNeo.Tests/Release.Tests.ps1,./Sources/Yohuke.DanmuNeo.Tests/WindowsInstaller.Tests.ps1 -CI"
```

原生安装生命周期测试使用独立注册表键、安装目录和快捷方式名称，在安装了 NSIS 的管理员 PowerShell 中执行；其他环境会跳过。这组测试会实际编译并运行安装器，覆盖两种安装范围、快捷方式、升级、迁移目录、文件占用和卸载保留额外文件：

```powershell
pwsh -NoProfile -Command "Invoke-Pester -Path ./Sources/Yohuke.DanmuNeo.Tests/WindowsInstaller.Integration.Tests.ps1 -CI"
```

Dock 改造的自动化覆盖布局往返与恢复、面板唯一性和实例复用、隐藏恢复、浮窗关闭、自定义预设、播放异步归属、跨面板插入、菜单命令、设置保存和退出顺序。原生播放器的实际声画连续性、中文 IME、系统菜单、多显示器缩放及原生控件在模态期间的交互，需要在目标桌面环境中另外验收；无头测试和发布签名检查不代替这些结果。
